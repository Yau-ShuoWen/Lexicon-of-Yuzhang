# 媒体存储模块计划（音频 + 图片）

> 基于现有 OSS 模块，做一套「方言词典」够用的媒体存储：音频开发最充分（分层存储、文件夹浏览、签名 URL、Service 层复用），图片只做简单版；视频不做。

---

## 一、背景与现状

| 已有资产 | 现状 | 问题 |
|---------|------|------|
| `multimedia/oss/OSSService` | upload / getUrl / delete 三个方法 | 对象全部塞进 `upload/` 前缀，无分层；无法浏览目录 |
| `multimedia/oss/OssTestController` | 连通性测试 | 可保留 |
| `multimedia/oss/UploadController` | 通用 `/upload` | 与业务解耦不够，业务方只能拿到 objectName，还要自己落库 |
| `multimedia/audio/*` | Audio Entity/Mapper/Service/Controller | 无文件夹概念；VO 不含路径信息 |
| `config/OSSConfig` | **密钥硬编码在代码里** | 与 `application.properties` 里的配置重复且不安全，必须修复 |
| 视频 | 无 | 砍掉，不做 |

## 二、设计目标

1. **音频最充分**：语义化分层存储、文件夹式浏览、签名 URL、删除、上传方法可在任意业务接口中复用。
2. **图片简单**：一套上传 / 浏览 / 删除，够用即可。
3. **视频不做**（方言词典用不上）。
4. **上传不依赖独立接口**：核心是 Service 层方法，任何 Controller 在接收"普通字段 + 文件"时直接调用，如"词条 + 录音"。

## 三、OSS key 前缀约定（虚拟文件夹）

对象名 = `类型根/业务路径/uuid.扩展名`，业务路径即虚拟文件夹层级，由调用方语义化传入：

```
audio/mdr/tone/1/<uuid>.mp3       ← 普通话某音调示例
audio/wuh/char/114514/<uuid>.wav  ← 武汉话某汉字示例
audio/ciyu/12345/<uuid>.m4a       ← 词条录音示例
image/avatar/1/<uuid>.png         ← 用户头像示例
image/ref/10086/<uuid>.jpg        ← 参考资料配图示例
```

规则：
- `类型根`：`audio` / `image`，禁止混用。
- `业务路径`：由调用方决定层级（方言代号、表名、主键等），中间层级可深可浅。
- 文件名：`UUID + 扩展名`，扩展名从原始文件名解析，统一小写。
- 天然不支持空文件夹（前缀约定的特性，符合"不需要的别开发"）。

## 五、数据库表设计

### 5.1 `audio` 表（沿用现有结构，不删字段）

| 列名 | 说明 |
|------|------|
| `id` | 主键 |
| `name` | 展示名（去扩展名） |
| `original_name` | 原始文件名 |
| `object_name` | OSS key，含虚拟文件夹前缀 |
| `format` | 扩展名 |
| `size` | 字节数 |
| `status` | 1 有效 / 0 删除（软删） |
| `create_time` / `update_time` | 时间 |

> 不加 `folder_path` 字段：文件夹信息已经完整蕴含在 `object_name` 前缀里，按文件夹查列表用 `object_name LIKE 'audio/{folder}%'` 即可，避免冗余字段。

### 5.2 `image` 表（新建，简单版）

| 列名 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT PK | 自增 |
| `name` | VARCHAR | 展示名（去扩展名） |
| `original_name` | VARCHAR | 原始文件名 |
| `object_name` | VARCHAR(500) | OSS key |
| `format` | VARCHAR(16) | 扩展名 |
| `size` | BIGINT | 字节数 |
| `status` | TINYINT | 1 有效 / 0 删除 |
| `create_time` | DATETIME | 创建时间 |

建表 SQL 随实施一起给出。

## 六、OSS 底层封装（`OSSService` 增强）

```java
public class OSSService {
    // 已有
    String upload(MultipartFile file);                     // 兜底保留
    String getUrl(String objectName);                      // 30 分钟签名 URL
    void delete(String objectName);

    // 新增
    String upload(InputStream in, String objectName);      // 直接按 key 上传
    String getUrl(String objectName, int expireMinutes);   // 自定义过期时间
    MediaDir browse(String prefix);                        // 虚拟文件夹浏览
}
```

`browse(prefix)` 实现要点：调用 `ossClient.listObjects(bucket, prefix, delimiter="/")`：
- `getCommonPrefixes()` → 下一层子文件夹列表
- `getObjectSummaries()` → 当前层文件列表（key + size + 最后修改时间）

返回结构 `MediaDir`：`{ path, folders: List<String>, files: List<MediaFileBrief> }`，文件附带签名 URL。

### 6.1 修复 `OSSConfig` 硬编码

```java
@Configuration
public class OSSConfig {
    @Value("${aliyun.oss.endpoint}")       private String endpoint;
    @Value("${aliyun.oss.accessKeyId}")    private String accessKeyId;
    @Value("${aliyun.oss.accessKeySecret}") private String accessKeySecret;
    // bucketName 由各 Service 自行 @Value 读取
}
```

> 注意 `application.properties` 里三个 OSS 值目前带前导空格（如 ` oss-cn-...`），一并 `trim()` 处理。

## 七、音频模块（最充分）

### 7.1 `AudioService` — 核心复用方法

```java
// 任何 Controller 都能调用：传文件 + 语义化文件夹路径
public Audio upload(MultipartFile file, String folderPath)
```

逻辑：校验格式白名单 → `objectName = "audio/" + folderPath + "/" + uuid + "." + ext` → OSS 上传 → 落库 → 返回 `Audio`（含 id / objectName）。

其它方法：
- `List<AudioVO> list(String folderPath)` — 按前缀查列表（空路径查全部）
- `AudioVO get(Long id)` — 详情，附带签名 URL
- `void delete(Long id)` — 删 OSS + 软删 DB

格式白名单：`mp3 / wav / aac / m4a / ogg / flac`。大小沿用全局 50MB 限制。

### 7.2 `AudioController` 独立接口（管理/调试用）

```
POST /api/audio/upload?folder=wuh/char/114514   multipart: file   → Audio（含 url）
GET  /api/audio/list?folder=wuh/char            → List<AudioVO>
GET  /api/audio/{id}                            → AudioVO（含签名 URL）
DELETE /api/audio/{id}                          → success
```

## 八、图片模块（简单版）

`ImageService` 与 `AudioService` 结构对齐，但只做基础能力：
- `Image upload(MultipartFile file, String folderPath)` — 白名单 `jpg / jpeg / png / gif / webp`，key = `image/{folderPath}/{uuid}.{ext}`
- `List<ImageVO> list(String folderPath)`
- `void delete(Long id)`

接口：

```
POST   /api/image/upload?folder=avatar/1
GET    /api/image/list?folder=xxx
GET    /api/image/{id}
DELETE /api/image/{id}
```

## 九、文件夹分层浏览接口（统一入口）

```
GET /api/media/browse?type=audio&path=wuh/
```

| 参数 | 说明 |
|------|------|
| `type` | `audio` / `image`，决定类型根 |
| `path` | 虚拟文件夹路径，不传则看根目录 |

返回示例：

```json
{
  "path": "audio/wuh/",
  "folders": ["audio/wuh/char/", "audio/wuh/word/"],
  "files": [
    { "key": "audio/wuh/demo.mp3", "name": "demo", "format": "mp3",
      "size": 102400, "url": "https://...签名URL..." }
  ]
}
```

实现：`OSSService.browse` + `MediaController`。前端可像文件管理器一样逐层下钻（点击 folder → 带上完整 path 再请求）。

## 十、业务接口中的复用示例（说明用法，不在本期开发）

需求：编辑词条时同时上传"词条 + 录音"。

```java
@PostMapping("/api/edit/ciyu")
public APIResponse<CiyuItem> edit(
        @RequestPart CiyuUpdate update,      // 普通字段（JSON）
        @RequestPart(required = false) MultipartFile voice  // 可选录音
) {
    Long id = ciyuService.update(update);
    if (voice != null && !voice.isEmpty()) {
        Audio audio = audioService.upload(voice, "ciyu/" + id);  // ← Service 层复用
        ciyuService.bindVoice(id, audio.getId());
    }
    return APIResponse.success(...);
}
```

音频、图片的 Service 方法就是为此准备的，业务方不需要感知 OSS。

## 十一、安全与配置

1. `OSSConfig` 改为读取 `application.properties`（消除硬编码密钥）。
2. `application.properties` 的 OSS 值去除前导空格。
3. 格式白名单：音频 / 图片各自校验，超范围直接报错。
4. 私有读 + 签名 URL：所有对外访问走 `getUrl`，不暴露长期公开链接。
5. 上传大小沿用 `spring.servlet.multipart.max-file-size=50MB`。
